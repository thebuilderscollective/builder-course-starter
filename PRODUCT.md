# Product

## Register

product

## Platform

web

## Users

Builder Course participants preparing for Build Day 1. Many are new to engineering
literacy and need each setup result explained in plain language without being
asked to understand the application internals.

## Product purpose

Prove that the participant's local Node.js setup, repository, coding agent,
private configuration, and Railway deployment work together. Success is one
public status page that reports the setup safely without revealing credentials.

## Positioning

One quiet checkpoint that proves the build kit is ready—and nothing more.

## Brand personality

Calm, rigorous, and encouraging. The checker should feel like a well-labeled
workbench: direct language, visible evidence, and no course-marketing hype.

## Anti-references

- A generic SaaS dashboard with charts, sidebars, upgrade prompts, or fake data.
- An AI demo with gradients, sparkle language, or product features unrelated to setup.
- A technical diagnostic screen that exposes secrets, raw response bodies, or stack traces.
- A pass/fail exam that makes a beginner feel blamed for a configuration problem.

## Design principles

- Stay inside setup scope; no course-product behavior belongs here.
- Name exactly what was checked and what remains manual.
- Never display, log, or return a private value.
- Let the repository teach through real examples, not placeholder documentation.
- Use the same safe workflow on macOS and Windows.

## Accessibility and inclusion

Meet WCAG 2.2 AA: readable contrast, visible focus, status communicated with
words as well as color, responsive layout, and reduced-motion support.
